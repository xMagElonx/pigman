# 一个游戏从立项到做出来：完整步骤

> 用途：参考卡。回答"一共要几步、每步什么时候算完、我会在哪一步卡住"。
> 与 `godot-dev-plan-M0-M7.md` 的区别：那份是**怎么做**（M0–M7 任务卡），这份是**全貌**（六阶段地图）。
> 检索时间：2026-10-12。

---

## 零、先纠正一个错觉

大多数教程把流程画成六等分。**它不是。** 按独立开发者的通常耗时，大致比例是：

| 阶段 | 大约占比 | 备注 |
|---|---|---|
| 1 立项 / 概念 | 极小（1–2 周） | 最容易被误当成"整个项目" |
| 2 预制作 | 约 10–15% | **决定生死的一格** |
| 3 制作 | 约 45% | 最长，也最像"上班" |
| 4 打磨 | 约 20% | 烂尾高发区 |
| 5 发行 | 按日历算 3–6 个月预热 | 常被误当成"最后一步" |
| 6 发售后 | 无终点 | 上线不是结束 |

后面所有判断都建立在这张比例表上。

## 一、六个阶段

### 1. 立项 / 概念

**这一阶段唯一要回答的问题：核心循环成不成立。**

- 产出物：一句话钩子（high concept）+ 3–5 条设计原则（design pillars）+ 目标平台 + **一个能跑的原型**
- 标准周期：**1–2 周**（AAA 才会给 3–6 个月）
- 常见错误：把它当成"写设计文档 / 扩世界观"。文档本身不构成进度。
- 判据：**如果两周内找不到"好玩"，这个创意熬不过十四个月。** 早点砍掉。

> 独立开发者常把第 1、2 格合并成"边做边验"，但**不能跳过**——只是形式上边做边验，不是真的不做。

### 2. 预制作

**这一阶段唯一要回答的问题：这个体验能不能以可控成本做出来。**

- 核心产出物：**垂直切片（vertical slice）**——一小段做到最终品质的内容，横跨玩法、美术、音频、性能
- 还要产出：每个系统 / 素材 / 里程碑的清单、带缓冲的排期、技术栈决定
- 标准周期：独立项目 1–3 个月（AAA 12–24 个月）
- 为什么切片关键：它同时回答两件事——① 体验成不成立 ② **做它到底要花多少钱**（这一步会暴露隐藏成本，比如动画工时、搭关卡的复杂度）
- 对《猪人》：**v0.2 的 M0–M7 全部在这一格。**

### 3. 制作

**内容量产。**

- 内容：关卡、角色、物品、剧情
- 系统：战斗、成长、经济、AI、存读档
- UX/UI：菜单、反馈、无障碍、新手引导
- 时长：独立项目 3–12 个月（AAA 2–4 年）
- 完成标志：**Alpha**——内容齐了，能从头走到尾
- 最大风险：范围失控（scope creep）。唯一的解药是"砍"。
- 管道在这个阶段才真正重要：命名规范、版本控制、每周构建

### 4. 打磨

**定义是"不加新功能"。** 只做四件事：修 bug、调手感、平衡、优化。

- 完成标志：**Gold**（可发行版本）
- 时长：独立项目 1–3 个月，**至少占总时长的 20%**
- 为什么新手容易在这里死：第 3 格每天都有新东西出现，第 4 格每天只是把已有的东西改好一点。没有新东西可做、只剩改——这是一个人最难熬的状态。**大部分人的仓库停在"能玩但很糙"的版本上。**

### 5. 发行

**最反直觉的一条：发行不是最后一步，它提前 3–6 个月开始。**

Steam 的具体数字（个人开发者，自查时间 2026-10）：

- 一次性入场费 **$100**（调整后总收入满 $1,000 可退）
- 分成 **70/30**（开发者 7 成；毛利超 $1,000 万里阶梯上调）
- 商店页与构建**分别送审**：商店页 2–5 个工作日，构建 3–5 个工作日，审核人员会实测运行
- **商店页设为「即将推出」后必须公开满 14 天**，后台才出现发行按钮
- 但预热期建议 **2–6 个月**：Steam 算法按**愿望单数量**决定上线曝光。7,000 愿望单的游戏和 500 愿望单的游戏，几乎总是前者卖得更好
- 非美国开发者需填 **W-8BEN** 税务表（中美有税收协定，可降低默认 30% 的预扣）
- **Steam Next Fest** 是最大的免费曝光机会（有开发者报告单次获得 5,000–20,000 愿望单），但它要求你有一个能玩的 demo
- 上线时机：周二 / 周三最好，别周五（周末无人处理问题），别撞夏促 / 冬促
- 首发 10–15% 折扣是常规做法，不是打折求生

> 一句话总结这一格：**游戏做得再好，商店页建晚了，等于没做。**

### 6. 发售后

补丁、内容更新、促销活动、社区运营、数据分析。上线不是终点线，是 live ops 的起点。

## 二、给《猪人》的位置

- **第 1 格已实质完成**：v0.2 计划书 + "我想做这个"的判断。
- **第 2 格进行中**：M0–M7 都属预制作，当前走到 **M2 / M7**。
- 按时间比例粗估，整条流程约走完 **8%**。

**这个数字的含义**：剩下 92% 的形状，要在走完这 8% 之后才会浮现。所以现在不去排 M5–M7 的细节是对的——现在写就是猜。

## 三、这份卡和最常被搞混的三件事

| 常被当成 | 实际是 |
|---|---|
| "写一份好的设计文档 = 立项完成" | 立项完成 = 有一个能跑的原型 |
| "把游戏做出来 = 上线" | 做完之后还有 20% 打磨 + 3–6 个月预热 |
| "先做完再看怎么卖" | 商店页要在做不完的时候就上线攒愿望单 |
