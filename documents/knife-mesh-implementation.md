# 刀身 · 二维轮廓挤出网格 —— 实现记录

> 任务：PIGMAN-ENG-001（工程侧 · 程基岩）
> 目标：把 `main.gd` 里刀身的 `BoxMesh` 换成「二维轮廓挤出」的网格，
> 让它在第一人称下呈现屠刀的**侧影**，而不是一块铁板。
> 上游规格：`documents/knife-profile-spec.md`（art-director / PIGMAN-ART-001）

---

## 0. 一句话结论

刀身现在是一条**14 顶点的二维轮廓**沿厚度方向挤出、并带**楔形截面**（刀脊 5 mm → 刃口 1.5 mm）、
分**三个材质面**（刀身 / 刀脊 / 刃口）的 `ArrayMesh`。
它的长度不再来自任何常量，而是**从这块网格的包围盒量出来**再注入命中胶囊 ——
「视觉改了、命中形状没改」这个旧 bug 在结构上不可能再发生。

自检四项全部 PASS，且这四项是在**规格顶点**上跑出来的（见 §5）。

---

## 1. 技术路线选择（为什么否掉另外两条）

| 路线 | 评估 | 结论 |
|---|---|---|
| **a) `CSGPolygon3D`** | 「折线 + 挤出」是现成的，代码最少。但法线由 CSG 的布尔求值决定，**薄片（5 mm）上容易出现发暗的脏法线**，刀身会「糊」；几何还是**运行期求值**的，每次改动都重跑一遍 CSG 管线。 | ❌ 否 |
| **c) 多个 `BoxMesh` 旋转拼装** | 最省事，但「方块感」正是要消灭的东西；而且拼不出连续的弧腹（规格 F2）与收尖（F1）。 | ❌ 否 |
| **b) `ArrayMesh` / `SurfaceTool`** | 逐顶点自己给法线 → **平面着色完全可控**，楔形斜面上的法线也精确；凹多边形交给内置 `Geometry2D.triangulate_polygon`；厚度 = 每个轮廓点各自的半厚。代价是代码比 CSG 长。 | ✅ **选它** |

**判断依据**：本项目是低模、全场只有一把武器 —— **性能不是约束，可控性与法线正确性优先**。
本规格的 F4（楔形截面）和 F5（亮刃线）都依赖「哪个面是什么法线、什么材质」的精确控制，
而这两件事恰恰是 CSG 最不可控的地方。

## 2. 改了哪些文件 / 函数

### 新建 `scripts/knife_mesh.gd`（`class_name KnifeMesh extends MeshInstance3D`）
- `SPEC_UV`：规格 §2.2 的 14 个归一化顶点（`Vector2(u, v)`）—— **形状的唯一来源**，
  文件顶部明写「改轮廓 = 改那份规格，不要在这里手改形状」。
- `SPINE_INNER_UV` / `EDGE_INNER_UV`：规格 §5.1 的两条内边界（以米制内缩 13 mm / 9 mm 后归一化）。
  仅用于把端盖切成三块，不改变外形轮廓。
- `@export blade_len / blade_width / thickness_spine / thickness_edge`：
  四个尺寸参数，每个的 setter 都调 `_rebuild()`。
- `_half_thickness(u)`：规格 §3 的楔形截面（脊 5 mm、主体 4.5 mm、刃口线性薄到 1.5 mm）。
- `_build_geometry()`：把轮廓挤出成网格，并按规格 **§5.1** 分三个 `surface` ——
  端盖**显式切成三块**（脊带 / 刃带 / 主体，各自单独三角化），侧壁按轮廓段 V1→V7 / V7→V14 / V14→V1 分面。
  ⚠️ 初版曾按 §5 初稿「先切整个 14 边形、再按三角面重心 u 分类」。art-director 复现证明这样分不出连续带
  （耳切三角又大又随机，重心不落在 u 带上 → F5 亮刃线失效）。已改为 §5.1 显式三分块，见 §5 的验证数字。
- `_tri_geo()`：法线取**几何法线**（这样楔形斜面上也是对的），再按参考方向纠正朝向。
- `_tri()`：保证三角形**绕序与法线一致**（Godot 背面剔除看绕序，不看法线属性 —— 否则会挖出破洞）。
- 对外接口：`blade_length()`（**直接量网格包围盒**）、`blade_center_z()`、
  `tip_local_position()`、信号 `profile_changed`。

### 改 `scripts/main.gd`
- `_build_weapon()`：删除 `Blade` / `Spine` / `Edge` 三个 `_mesh_box`，
  换成一个 `KnifeMesh` 节点（`Blade`），并把 `BladeMid` / `ShapeCast3D` 的引用存为成员。
- 新增 `_sync_blade_geometry()`：**「碰撞箱 = 模型的函数」的唯一执行点**。
  从网格包围盒量长度、从节点位置量中点，注入 `MeleeWeapon.blade_length / blade_center`，
  并把 `BladeMid` 与 `ShapeCast3D` 挪到新中点。它被 `KnifeMesh.profile_changed` 触发。
- 常量区：删掉 `BLADE_SIZE` / `BLADE_CENTER_Z`（尺寸已搬到节点上），只留 `BLADE_ROOT_Z`（刀根位置）。
- `_tuner_entries()`：+4 根刀身滑条（长 / 宽 / 刀脊厚 / 刃口厚）。
- `Collar` 高度 `0.17 → 0.13`（规格 §5.6：新刀根宽约 0.11 m，0.13 恰好盖住，属美化项）。

### 改 `scripts/weapon.gd`（**唯一的改动，且只碰几何，不碰任何手感参数**）
- 给 `blade_length` 加了一个 setter，赋值即调 `_rebuild_shape()`：
  ```
  var blade_length := 0.80:
      set(v):
          blade_length = v
          _rebuild_shape()
  ```
  理由：它以前是个哑变量，改了长度得靠人记得再调一次 `_rebuild_shape()`，忘了就又是
  「视觉改了、判定没改」。绑死之后这件事不可能发生。
  `windup / active / recovery / hitstop / shake_strength / swing_angle_deg / swing_tilt_deg /
  hold_roll_deg / hold_pitch_deg / hold_yaw_deg / blade_radius` **一个都没动**。

### 未改
`tuner_panel.gd`、`tuning_store.gd`、`target_dummy.gd`、`player_controller.gd`、`graybox.gd`
均未改动。新增的 4 个参数落在 `TuningStore.key_of()` 的 `world.*` 分组
（`KnifeMesh` 不是 `PlayerController` / `MeleeWeapon`，走 fallback），与 `world.dummy_*` 不冲突。

**关于「收尖程度 / 刃口弧度」两根滑条**：任务原希望把它们做成 `@export`。但规格已给出
**固定的 14 顶点轮廓**，并明确「直接读它、用里面的顶点，不要自己另设计」。
形状（收尖 / 弧腹 / 不平行长边）此刻**就是那 14 个点**，再用滑条去捏会与规格打架。
因此收尖与弧度**退化为规格里的一条曲线**，由 `SPEC_UV` 固定；面板保留的是规格 §3 建议的
四个可调量（长 / 宽 / 脊厚 / 刃厚）。**这是对任务「尽量」二字的取舍，已在此写明，供你拍板。**

面板计数：`玩家 12 + 武器 11 + 刀身 4 + 世界 2 = 29` 项。
`tuner_panel.gd` 的 ScrollContainer 方案保持不变 —— 实测滑条区最小高 661 px，
固定部分 226 px，合计 919 px > 900 px 视口，**自动出现滚动条，不被裁掉**（自检已打印该数值）。

## 4. 碰撞箱不变式（本项目的血泪坑）

> **碰撞箱不应该是一个数字，应该是模型的一个函数。**

数据流（单向，无第二份数字）：

```
KnifeMesh.SPEC_UV ──挤出──► ArrayMesh
                              │  get_aabb()
                              ▼
              KnifeMesh.blade_length() ──► main._sync_blade_geometry()
                              │                    │
                     blade_center_z()              ▼
                                        MeleeWeapon.blade_length (setter)
                                                   │
                                                   ▼
                                          _rebuild_shape() ──► CapsuleShape3D
```

- `main.gd` 里**没有任何**关于刀身长/宽/厚的数字。
- 拖任意一根刀身滑条 → `profile_changed` → `_sync_blade_geometry()` → 胶囊立刻重建。
- 自检第 ⑥ 项就是这条链的活证据：把刀身从 0.40 拖到 0.30，胶囊总高 **0.6500 → 0.5500**。

> **刃口 metallic 0.90 → 0.50（PIGMAN-ENG-002，team-lead 拍板）**：规格 §4 的 0.90 是
> 「理想反射环境」下的取值；而本灰盒环境无天空、无反射探针（`AMBIENT_SOURCE_COLOR`）+ 一盏平行光，
> 高金属度几乎没有东西可反射，0.90 的刃口反而可能比 metallic 0.40 的刀身还暗 —— F5「最亮的一条边」不成立。
> 因此只降 metallic、保留 albedo(0.76,0.77,0.78) 与 roughness(0.22)。**这一步不加 emission**（不够亮时才考虑）。

> **§5.1 修正说明**：初版按「整块耳切 + 重心 u 分类」时，刀脊面每盖只有 0~1 个三角、刃口面
> 只有弧腹上一块补丁 —— **刀面上根本没有连续的暗脊带 / 亮刃带**，F5 必然失败。
> 改为显式三分块后，脊带 / 刃带各自成为贯穿刀面的连续条带（上表 u/v 范围即证据），
> 且三块并集面积残差为 0（不重叠、不漏空）。这是 art-director 复核时发现的规格初稿疏漏，
> 与顶点点位无关；顶点仍是 SPEC_UV 原样。

## 7. 风险与遗留（需要你/玩法拍板）

1. **长宽比从 1.82:1 拉到 2.70:1（宽 0.22 → 0.148）**。
   规格 §2.4 的实测依据是台博藏「殺豬刀」30:11.1 cm。**长度仍是 0.40 m**，
   所以**打击距离、刀尖距眼（0.958 m）、命中胶囊长度都没变** —— 这一条纯视觉，无玩法回归。
2. **可选方案**：规格 §2.4 提出可把刀身缩到真刀实尺 **0.30 × 0.111 m**，
   代价是刀尖距眼掉到约 0.86 m、命中胶囊与手感需重调。**这是玩法取舍**，我未采纳，等你们拍板。
3. **未在真实窗口做肉眼确认**：所有验证都在 headless 下用数字完成。
   「0.3 秒内读成屠刀」这条（规格 F1–F5 的组合判定）是**肉眼验收**，需要你在窗口里跑一次。
   建议对照规格 §6：把 `│ 持刀翻转 roll °` 在 −90 / −45 / 0 之间拖动，看五条特征是否都在。
4. **`weapon.gd` 有 1 处改动**（`blade_length` 加 setter，纯几何、不碰手感参数）。
   若你要求该文件零改动，替代做法是 main.gd 在同步时调用 `_rebuild_shape()` —— 但那更丑、更脆，
   故我选了前者。**请确认这一处是否可接受。**（team-lead 已确认：可接受，保留。）
5. **刃口 metallic 用了 0.50，不是规格 §4 的 0.90**（见 §5 的说明）。
   若窗口里亮刃线仍不够亮，下一步是把刃口 `emission` 提到能量 ~0.15–0.3；**先只降 metallic**。
6. **肉眼验收仍待完成**：以上全部是 headless 数字验证。F1–F5 的「0.3 秒读成屠刀」是肉眼判断，
   请对照 `documents/knife-profile-preview.svg` 在窗口里拖 `│ 持刀翻转 roll °` 验收。

`_build_weapon()` 里那**三个硬编码盒子**（`Handle` / `Butt` / `Collar`）整段换掉，改成

写死、不给滑条（§7.4 建议）：**柄舌插入深度 0.050 m**（`TANG_INSERT`，藏在木头里、看不见）；
**柄舌直径 0.024 m**（`NECK_DIA`）；**柄尾加粗段长 1.5 cm**（`BUTT_LEN`）。

参数名跟随 §7.4（`handle_dia` 而非 `handle_diameter`；`grip_offset` 语义按 §7.3.3 = Z 平移）。
全部 target 为 `self`（Main 节点）→ `TuningStore` 落 `world.handle_*` / `world.grip_offset` /
`world.neck_len` / `world.butt_bulge`，与 `world.blade_*` / `world.dummy_*` **不重名**。

## 11. 结构性规矩（本轮新增，别拆）

1. **刀根固定在 `z = BLADE_ROOT_Z(−0.110) − grip_offset`。** 刀身几何不动；挪的是**整坨武器**。
2. **柄长只往身后长。** 木柄前端钉在柄舌上，`grip_offset` 不动时刀尖距眼、绕肩半径都不变。
3. **柄尾加粗段钉在柄尾上。** `handle_len` 变长，它跟着走（自检③给了三个数值）。
4. **`_rebuild_handle()` 末尾必调 `_sync_blade_geometry()`。** 刀根一动，命中胶囊立刻重建 ——
   「视觉改了、判定没改」这条链原样保留。
5. **柄身是圆柱**，节点绕 X 转 90° 让轴对齐 Z，否则柄会竖着穿过刀身（§7.2.4）。
