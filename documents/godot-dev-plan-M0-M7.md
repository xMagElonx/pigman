## 3. 怎么跑（别跳）

1. Godot → Import → 选 `project.godot` → Import & Edit
2. F5
3. **先别动。** 锁定鼠标（点一下画面）
4. WASD 走一圈，按住 Shift 冲刺，**注意地上的刻度线**
5. **鼠标左键 挥砍。** 两个靶子：左手边近靶（1 米），右手边远靶（4 米）
6. Tab 开关面板 · R 复位靶子 · **空格 跳跃（默认关，见 4.1）** · Esc 释放鼠标

> 面板最后一行有读数，那是你的验收工具：
> **「挥击 N · 命中 M」** —— 一次挥击打五下这个 bug 会在这里现形，不用靠眼睛。
> **「臂展 X.XX m」** —— 刀的实际够到距离。它必须永远 = 视觉刀尖 + 刀刃容错（见第 12 节）。
> **「方向偏差 N°」** —— 速度方向和你朝向差多少度。0° = 身体听话。
> **「跳高 X.XX m」** —— 当前 `jump_velocity` 对应能跳多高；显示「未开」= 值还是 0。
> **「靶子 6/6 · 6/6」** —— 剩余血量；倒地时会变成「2.1s 后复位」。
> **面板最下面那行绿字** —— 每次自动保存 / 存快照 / 恢复默认都会在这里报一句。

**场景里所有的「条」是什么意思，见第 4 节。**

## 4. 指示条与参数速查表

### 4.0 画面上你能看到的「条」

| 你看到的 | 叫什么 | 它代表什么 |
|---|---|---|
| 地面上一道道横线 | **刻度线**（每 2 米一道，共 4 道） | **一把尺子。** 4 m/s ≈ 每秒走过 2 格。没有它，你把 `acceleration` 从 45 拖到 120，眼睛根本看不出区别 |
| 左右墙上那两根**橙色竖条** | **门框标记** | 北墙门洞的边缘位置。它标的是「可行动方向」—— 不是装饰 |
| 面板里那 **20 根横条** | **滑条** | 每一个 = 一个手感参数。往右拖 = 值变大 |
| 滑条右边的**数字** | 当前值 | 实时值，不是目标值 |
| 面板底部**四行字** | **读数** | 仪表。不是给你调的东西，是给你判断的 |
| 面板底下**三个按钮** | **存快照 / 取快照 / 恢复默认** | 见 12.3 —— 这是「改动会不会丢」的答案 |

**判据**：不是「屏幕上有几个条」，而是 —— 你改一个数字之后，**能不能从这些条上看出它生效了**。看不出来，那个参数就是不可调的。

### 4.5 两张专用的对照表

| `steer_rate_deg` | 横向漂移 | 手感 |
|---|---|---|
| 4000 | 约 0.11 m | 指哪打哪 |
| **2400（默认）** | **0.13 m**（3 帧对齐） | **听话。M1–M3 该用的值** |

## 5. 靶子 vs 敌人 —— 一次顺序修正（2026-10-12）

**你的原话：**「移动什么的都是服务于砍杀的，是不是先做个敌人再做个武器出来我好知道打起来爽不爽。」

**对的那一半：** 完全对。移动不是战斗的前置，**移动是战斗的一部分**。在一个空房间里拖滑条，你没有可失去的东西 —— 也就分不出「这个身体听我的话」和「这个身体只是没被我用来做任何事」。所以靶子必须在移动调参之前就位。这是对 M1 原设计的修正。

**要改的那一半：** 顺序不是「敌人 → 武器」，而是：

```
靶子（静态，但会反应）
   ↓
武器（挥砍 + 反馈）
   ↓
移动参数 ← 到这一步才有意义
   ↓
敌人 AI（M3）
   ↓
断肢 / 移植（M4）
```

**为什么 AI 排在最后：** 「爽不爽」的变量只有三个 —— ① 挥击窗口对不对 ② 反馈够不够 ③ 目标有没有反应。一个会移动、会反击、会绕后的目标，会往里面塞进第四个变量（AI 行为）。于是你测出「不爽」的时候，分不清是哪一个坏了。**先把三个已知变量调定，再引入第四个。**

**所以靶子刻意了什么都不做：** 不移动、不攻击、不躲闪、不用导航。它只有一件事：**被打，然后有反应**（后仰 + 闪白 + 倒地）。

**代价你要知道：** 静态靶子测不出「追着移动目标砍」。那正是移动参数（`steer_rate_deg`、`deceleration`）真正要吃紧的地方，也是 M3 一到位就会立刻暴露的东西。**这不影响现在该做的事** —— 现在要的是基线，不是全貌。

## 6. M3–M7 → Godot 实现细节

### M3 · 一种敌人

**动哪里：** 复制 `target_dummy.gd` → `scripts/enemy.gd`（改 `CharacterBody3D`）+ 状态枚举。

```
IDLE → APPROACH → WINDUP → ATTACK → RECOVER → (受击) STAGGER → (重击) DOWN
```

**两个取舍：**
- **先别上 NavigationRegion3D。** 房间是空的，`(player.position - position)` 归一化后直线追就够。省掉一整套导航系统，也省掉一堆「怪物卡在门框上」的 bug。
- **可读性 > 聪明。** `WINDUP` 必须长到玩家能用眼角看见。你 v0.2 写「敌人必须主动施压」，但更前置的是：**压力必须看得见**。攻击前的收势、声音、姿势变化，至少给两样。

**派活话术：**
> 为一个 Godot 4 的 CharacterBody3D 敌人实现状态机：IDLE / APPROACH / WINDUP / ATTACK / RECOVER / STAGGER / DOWN。每个状态的进入条件、持续时长、可被哪些事件打断，先用 @export 暴露时长参数。不做寻路导航，只做直线接近 + 保持距离。不做伤害数值，只输出状态切换的时间戳日志。

**验收补一条：** 敌人第一次攻击你之前，你**看见了**它要攻击。看不见，WINDUP 就等于没有。

### M4 · 切断与断肢

**动哪里：** 新增 `scripts/detachable_part.gd`（`RigidBody3D`）；敌人模型上放 `Marker3D` 命名 `arm_l / arm_r / leg_l / leg_r`，每个挂一份独立的碰撞体。

**在 M2 已经给你留好了接口：** `TargetDummy.take_hit(info: Dictionary)` 收的就是字典，M4 直接往里加 `part_name` 和 `impulse` 两个键，**不用改任何调用方**。

**切断流程（四步，不要合并）：**
1. 命中该区域且冲量超过阈值 → 把该 Marker 下的 `MeshInstance3D` 从敌人身上摘掉
2. 在原地实例化一个 `RigidBody3D`，把摘下来的网格塞进去
3. 给它一个沿攻击方向的初始线速度
4. 把部位名写进敌人的 `disabled_parts` 数组 → 状态机读它，缺 `arm_r` 就禁掉那套攻击

**这就是你 v0.2 写在 3.1 的「预设切断点」的全部实现** —— 没有网格切割，没有布尔运算，只有「摘掉、换一个物体、记一个标记」。它便宜，而且它足够。

**派活话术：**
> 在 Godot 4 中实现预设断肢：敌人身上若干部位各有独立命中区域，命中且冲量超阈值时，把该部位的 MeshInstance3D 从敌人节点摘下，创建一个 RigidBody3D 接管这个网格并赋予沿攻击方向的初速度，同时把部位名加入敌人的 disabled_parts。要求断开阈值用 @export 暴露，并要求敌人其它系统能读到 disabled_parts。不做网格切割，不做血液特效。

**你必须亲手做的验收：** 切断后**把视线移开**，只看画面边缘 + 听声音，判断你是否知道它「少了什么」。判断不出，说明断肢现在只是特效，不是系统 —— 而你原则 3 写的正是「系统产生后果」。

### M5 · 环境交互

**只做一种组合：** 一扇门 + 一个凹槽。把断肢放进凹槽 → 门开。

**统一交互规则（对应你 3.2）：** 新增 `scripts/interactable.gd`，每个可交互物上写 `supported_actions: Array[String]`。刀、断肢、门锁、线缆都实现同一个接口，但**各自只开放合乎结构的行为**。

> 关键取舍：不要让所有物体变成同一套可交互物。宁可 5 个物体各支持 1–2 种行为，也不要 1 个物体支持 20 种。前者玩家能形成稳定预期，后者会让人觉得「这游戏到处都是 bug」。

### M6 · 镜子复活

**动哪里：** `scripts/checkpoint.gd`（`Area3D`）+ `main.gd` 里加一个 `reset_level()`。

**按你 v0.2 的取向实现（整个房间重置，不保存复杂状态）：**
最省事的做法是**把房间 / 玩家 / 靶子 / 敌人全放进一个 `Node3D "Level"`**，复活时 `queue_free()` 整个 Level 再重建一次。一行代码换掉一整套状态序列化 —— 在原型阶段这是绝对正确的交易。

**派活话术：**
> 实现一个 Godot 4 检查点：玩家进入 Area3D 时记录当前检查点；玩家死亡后经过短暂停顿，销毁并重建整个 Level 节点（房间 + 玩家 + 敌人），把玩家放回最近检查点。要求：不保存敌人个体状态，不保存拾取历史；死亡过渡期间冻结输入。实现后列出重置了哪些东西、哪些没有。

## 7. 我给 v0.2 补四条

**第一条：M2 的验收少了「手感」那一整半。**
你写的是「能稳定命中；不会多帧重复结算；切中与挥空有清楚差别」——前两条是**正确性**，第三条是**手感但不可测**。补一条可测的：

> **闭眼（或背对屏幕）时，也能分辨切中与挥空。**

靠音效 + 顿帧 + 屏震。这一条不过，等 M3 之后再补就晚了 —— 因为那时候你已经把「手感差」归因到敌人身上了。

**第二条：M2 的声音钩子是空的，这是刻意的。**
`weapon.gd` 里 `_play_swing_sound()` 和 `_play_hit_sound()` 是两个空函数。它们不是我忘了 —— **声音是《猪人》的签名，属于作者性，不该由 AI 塞占位素材。**
代价是：上面那条「闭眼分辨」的验收，在你填进自己的声音之前**只能靠顿帧和屏震裸考，大概率过不了**。这是设计，不是缺陷。

**第三条：没有版本对照的习惯。**
每天结束两件事，成本 2 分钟：一行 `git commit` + 一段 10 秒录屏存到 `documents/clips/`。它会在第 5 天救你一次。

**第四条：「看不懂的代码不许进项目」。**
你是零代码起步，AI 写的代码**能跑，但不一定对**。硬规矩：

> 任何 AI 交付的脚本，AI 必须同时说清三件事：**它放在哪、它依赖什么、参数在哪改。**
> 说不清，就不要。不是因为优雅 —— 是因为两天后你得自己改它。

## 11. 三条报错的修复记录（2026-10-13）

### 11.1 转身时「莫名其妙的左右位移」

**先给结论：这不是代码错误，这就是你在 10-12 要的第 3 条「急转 → 被甩出去」。**

自检实测（冲刺 8.5 m/s、原地转 90°）：

```
+ 1 帧  速度方向偏差 78.0°  横向 -0.139 m
+ 4 帧  速度方向偏差 42.0°  横向 -0.477 m
+ 8 帧  速度方向偏差  0.0°  横向 -0.607 m   ← 收住了
```

偏差角严格以 12°/帧（＝720°/秒）收敛到 0 —— **数学没错，是参数。**

**为什么它读起来「莫名其妙」而不是「有重量」**：视角是**瞬间**跟着鼠标转的（相机焊在身体上），速度方向却是**慢慢**追的。第一人称看不见自己的身体，所以同一件事读起来不是「我的身体有惯性」，而是「世界莫名往旁边滑」。**可见与不可见的错配，才是「莫名其妙」的来源。**

**做了三件事：**

1. **默认值 720 → 2400。** 漂移从 0.607 m 降到 0.133 m，3 帧对齐 —— 手感上等于「指哪走哪」。
   为什么改：本项目已定下的规则是 **M1–M3 身体必须听话，M4 之后才引入别扭**（见 `m1-pre-registration.md`）。0.6 米的横滑是 M4 该做的事，不是基线该有的。
   **想现在就要那个手感？把滑条拖回 720 以下，一次拖动就能回来。**
2. **新增读数「方向偏差 N°」**（＝速度方向与朝向的夹角）。0° = 听话，转身时瞬间飚到 90~180° 再回落。
   这才是「莫名其妙」的解药：**它把不可见的量变成了可读的数字。** M4 判断「身体是不是开始不听话了」，也全靠这个读数。
3. **新增滑条 `turn_speed_keep`（默认 1.0 = 关闭）。**
   原地转身时速度方向会分开但速度**不减** —— 那不是有重量，是**磁悬浮侧滑**。拖到 0.5，急转会明显掉速。
   ⚠️ 实测发现它与 `steer_rate_deg` 耦合：转向 2400 时 3 帧就转完，这个参数几乎没发挥空间。**想用它，先把转向拖低。**

**⚠️ 这一条我没有替你选。** 你 10-12 要它，10-13 说它是 bug —— 两个要求互相矛盾，只有你知道现在要哪个。已经把三个数字和各自的漂移量列在 4.5，滑条上 30 秒就能分辨。

### 11.2 靶子被击杀后无法重新生成

**先说个意外结论：`respawn()` 和 R 键本身都是好的**（自检：按 R 之后 hp=6、down=false）。所以「无法再生」另有原因，一共三条：

| 原因 | 真 bug？ | 修复 |
|---|---|---|
| **屏幕上从没写过 R 是什么键** —— 只有终端启动时打印过一行，不跑终端就看不到 | 是（可用性） | 写进面板提示行：`R 复位靶子` |
| **一个练习靶本来就该自己站起来**，而不是等你按 R | 是（设计缺口） | 新增 `auto_respawn_delay`，默认 **2.5 秒**，面板可调 0–10 |
| **倒地后碰撞体没关** —— 自检抓到 `碰撞disabled=false`。视觉躺下了，碰撞胶囊还立着 → 一根看不见的柱子把你撞停 | **是（真 bug）** | `_fall()` 里连碰撞一起关；`respawn()` 按 `_active` 状态恢复 |

第三条是这次最有价值的一个发现：**它和 `set_active()` 当初犯的错是同一个错**（只改视觉、不改碰撞）。这类错误的特征是「不报错、但你会撞到空气」。

### 11.3 左侧滑条栏显示不完整、无法上下滑动

**原因（数字）**：19 根滑条，原来是「标签一行 + 滑条一行」的竖排，需要 **958 px** 高，从 y=24 开始 → 底部 **982 px**，而窗口只有 **900 px**。溢出 82 px，而且**没有滚动容器** → 最下面两行永远调不到（包括那条最重要的读数）。

**三处修复：**

1. **标签 + 滑条 + 数值压到同一行** → 滑条区从 958 px 降到 **431 px**
2. **滑条区套 `ScrollContainer`** → 参数再加也不会掉出屏幕（M4 断肢还要加一批）
3. **面板高度每次窗口变化时重算**，永远不超过视口；标题和底部读数**不进滚动区**（读数是仪表，不能滚走）

**修复后实测**：19 行 · 固定部分 129 px + 滑条区 431 px + 边距 = **合计 592 px**，900 px 窗口 **余 308 px**。

### 11.4 本次的验证

| 检查 | 结果 |
|---|---|
| 面板高度 | row=19，合计 592 px vs 窗口 900 px，**放得下** |
| 转身 A（steer 2400 · keep 1.0） | 横向 **0.133 m**，最低速度 8.50（不掉），第 3 帧对齐 |
| 转身 B（steer 400 · keep 1.0） | 横向 **1.147 m**，最低速度 8.50（不掉），第 14 帧对齐 |
| 转身 C（steer 400 · keep 0.5） | 横向 **0.876 m**，最低速度 **5.50**（掉 3.0），第 14 帧对齐 |
| 靶子倒地 | `碰撞disabled=true` ✓ |
| 靶子自动复位 | 2.5 s 后 hp=6、down=false、碰撞恢复 ✓ |

**过程中修掉的自己人的错**：`turn_speed_keep` 第一版是直接乘当前速度，转 90° 那 8 帧里每帧乘一次 = 复利，速度崩到 1.73 m/s（那是刹车不是掉速）。改成改**目标速度**后稳定在 4.25。

**测试脚本自身也翻过两次车**（值得记）：第一次玩家在冲刺时撞到东墙、第二次在转身时撞上远靶，都把「最低速度」污染成了碰撞结果。所以：**凡涉及"位移/速度"的自动测试，必须先瞬移到一个没有障碍的位置并直接给速度。**

## 12. 三条修复记录（2026-10-14）

> 这一轮是**你第一次跑起来之后**报的问题。这件事本身比这三条重要：
> 前 6 次提交都建立在「我验过它不报错」上，而这 3 条里至少有 2 条，
> **只有真的坐下来砍过才知道**。所以下面每条都先给数字，再给原因。

### 12.1 看着砍到了，却经常判不到

**先量化。** 自检读出的两组数字：

```
刀身：中心距手腕 0.660 m，全长 1.150 m  →  刀尖 1.235 / 刀根 0.085
命中形状：球半径 0.420 m，球心在刀身中点 0.660 m  →  检测最远 1.080 m
缺口：刀尖 1.235 − 检测最远 1.080 = 0.155 m 判不到
```

**根因不是「长度写错了」，是「形状用错了」。**

旧实现是一个 **半径 0.42 的球，球心走在刀身中点**上。这带来两个方向相反的错误：

| 方向 | 视觉 | 检测 | 结果 |
|---|---|---|---|
| **沿刀身（长度）** | 刀尖 1.235 m | 球心 0.660 + 半径 0.420 = **1.080 m** | **尖端 15.5 cm 是断的** → 「看着砍到了却判不到」 |
| **垂直刀身（宽度）** | 刀刃厚 0.085 m | 球直径 **0.840 m** | **宽了约 10 倍** → 隔空砍中 |

所以你同时有两个 bug，而只有「够不着」那个被你感觉到了 —— 因为「隔空砍中」在打一个大靶子时几乎看不出来。

**边界实测（同一套自检脚本，改前 / 改后）：**

| 靶子距离 D | 旧实现 | 新实现 |
|---|---|---|
| 1.0 m | 命中 ✓ | 命中 ✓ |
| 1.3 m | 命中 ✓ | 命中 ✓ |
| **1.6 m** | **未命中 ✗** | **命中 ✓** |
| 1.9 m | 未命中 ✗ | 未命中 ✗ |
| 2.2 m | 未命中 ✗ | 未命中 ✗ |

有效距离整体推后了约 0.3 m，**缺口消失**。

**修法（三步）：**

1. **形状换成沿刀身的胶囊**（`CapsuleShape3D`），不再是球。
2. **长度从 Blade 网格的 `size` 读出来**，注入给武器 —— 不再手填。
   于是「模型改了但碰撞箱没改」在**结构上**不可能再发生，因为碰撞箱是**从模型算出来的**：
   ```
   reach = 刀身中点 + 刀身长 × 0.5 + 刀刃容错
   ```
   自检断言：`reach − visual_tip == blade_radius`（实测 0.0700 = 0.0700 ✓）。
3. **新增滑条 `刀刃容错 radius m`**（默认 0.07 = 横向总宽 14 cm）。这是「擦到算不算中」的唯一旋钮：
   往下拖（0.02）只认真正的刀刃，手感很硬；往上拖（0.20）开始隔空砍中。

**顺手修掉的一个隐患**：旧 `_detect()` 里写了
```gdscript
_shapecast.global_transform = Transform3D(Basis(), _prev_mid)
```
它会把形状的旋转重置成 identity。以前形状是**球**，球没有朝向，所以看不出问题；换成胶囊之后，那样写会让胶囊**永远竖着** —— 等于又错一次。现在改成不动节点、只把世界位移转进局部空间（`target_position` 是局部坐标）。

### 12.2 跳跃速度默认一直是 0

**结论：这是刻意的，不是坏了。** 代码注释里写着理由 —— v0.2 计划书里**没有跳跃**。

但你的困惑是合理的，而且**责任在我**。真正的问题是三条叠在一起：

1. 默认值 0（刻意）→ 你看到 0，以为是 bug。
2. **触发键是 Godot 内置的 `ui_accept`，而屏幕上从来没有写过「按什么键跳」。** 你拖了滑条、按了各种键、没反应 —— 自然会判定「跳跃坏了」。
3. **改了也存不住**（因为第 12.3 条当时没解决）→ 关掉重开又回到 0。三个问题连在一起，互相强化。

**三条修复：**

1. **起一个自己的 `jump` 动作（空格），不再借 `ui_accept`。**
   好处是它出现在 `input_actions.gd` 的 `ACTIONS` 表里 —— 可搜索、可改、跟 Git 走；而 `ui_accept` 是引擎内置的，屏幕上找不到、也改不了。
2. **屏幕和标签都写上键位**：启动日志写「空格 跳跃」，面板标签写 `jump_velocity  跳跃(空格)`。
3. **读数直接显示「跳高 X.XX m」** —— 由 `jump_velocity² / (2 × gravity)` 算出来。拖滑条时立刻看见「这个数字意味着跳多高」，不用自己算。
   （实测 `jump_velocity = 6`、`gravity = 24` → 理论 0.750 m，实测峰值 **0.802 m**，差 7%，是 60 FPS 离散积分的正常误差。）

**⚠️ 但我建议你 M2 阶段先别开它。**

理由是第 5 节那套逻辑的延续：「爽不爽」的变量只有三个。跳跃会塞进第四个 —— 你分不清一次「砍空了」是因为跑位不对，还是因为你人在空中、刀的高度变了。

**要不要给《猪人》跳跃，是个设计问题，不是技术问题。** 地铁车厢层高 3 米、天花板默认关着，跳跃在这里没有战术价值；但如果你玩的时候反复产生「我想跳过去」的冲动，那就是需求。**那个冲动才是信号，不是这条滑条。**

### 12.3 改了参数存不住

**新增一个文件 `scripts/tuning_store.gd`，三层：**

| 层 | 存在哪 | 什么时候发生 |
|---|---|---|
| **自动保存** | `user://tuning.cfg` | 拖动停止 **0.6 秒**后写盘；下次启动自动读回。**你什么都不用按** |
| **快照** | `user://tuning_snapshot.cfg` | 按「存快照」记住现在这一版；按「取快照」随时回到它 |
| **恢复默认** | 代码里的 `@export` 初值 | 按「恢复默认」。初值在启动时采集一次，**永远不会被你的拖动污染** |

**快照那一层是为这句话写的**：调参最大的敌人不是调不出来，是**你忘了昨天那版什么样**。
工作流是：调到满意 → 存快照 → 继续实验别的方向 → 不满意就取回来。30 秒一轮，不用 Git。

**实际路径**（Windows）：
```
C:\Users\<你>\AppData\Roaming\Godot\app_userdata\PIGMAN\tuning.cfg
```
它是纯文本，想手改也行，改完重启项目生效。

**为什么不把值直接写回 `.gd` 文件？**
脚本归 Git 管。你每天 `commit` 的应该是「我改了什么设计」，不是「我把 walk_speed 拖到了 4.3」。**手感值属于「这台机器上的我」，不属于「这个项目的代码」** —— 两者混在一起，三个月后你分不清哪些是设计、哪些是临场试出来的。
