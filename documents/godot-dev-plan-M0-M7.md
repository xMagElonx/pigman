## 3. 怎么跑（别跳）

1. Godot → Import → 选 `project.godot` → Import & Edit
2. F5
3. **先别动。** 锁定鼠标（点一下画面）
4. WASD 走一圈，按住 Shift 冲刺，**注意地上的刻度线**
5. **鼠标左键 挥砍。** 两个靶子：左手边近靶（**要走到 1 米内**），右手边远靶（4 米外，测跑位）
   ⚠️ 屠刀是**短兵器**：刀尖距眼约 **0.96 m**，**砍不到 1.5 米外的东西**。这是刻意的
6. Tab 开关面板 · R 复位靶子 · **空格 跳跃** · Esc 释放鼠标
7. **按空格跳一下，然后看墙上那条橙色的横线** —— 它在 1.0 m 高处。跳到它上面还是下面？
8. **跳起来之后按 WASD —— 你会发现改不了向。** 这是本轮改的第三件事，见第 15 节

> 面板最后一行有读数，那是你的验收工具：
> **「挥击 N · 命中 M」** —— 一次挥击打五下这个 bug 会在这里现形，不用靠眼睛。
> **「刀尖距眼 X.XX m」** —— 刀真正够得到多远。**注意它和武器内部说的「臂展」不是一个数**：臂展从手腕量，这个从眼睛量（见 12.1）。
> **「刀面偏角 N°」** —— 刀刃那一面有多正对着你。**0° = 刀面正对镜头，90° = 你只剩刀背那 3 厘米可看。** 拖「持刀翻转 roll」时盯这一格。
> **「方向偏差 N°」** —— 速度方向和你朝向差多少度。0° = 身体听话。
> **「地面 / 空中(操控 X.XX)」** —— 你现在在哪，以及空中还剩下多少操控权。
> **「跳高 X.XX m · 实测 X.XX」** —— 前半是公式算的，后半是**你刚才真的跳了多高**。两者差多少，就是这一帧一步的真相。
> **「靶子 6/6 · 6/6」** —— 剩余血量；倒地时会变成「2.1s 后复位」。
> **面板最下面那行绿字** —— 每次自动保存 / 存快照 / 恢复默认都会在这里报一句。

**场景里所有的「条」是什么意思，见第 4 节。**

## 4. 指示条与参数速查表

### 4.0 画面上你能看到的「条」

| 你看到的 | 叫什么 | 它代表什么 |
|---|---|---|
| 地面上一道道横线 | **刻度线**（每 2 米一道，共 4 道） | **水平尺。** 4 m/s ≈ 每秒走过 2 格。没有它，你把 `acceleration` 从 45 拖到 120，眼睛根本看不出区别 |
| **东西两墙上一道道横线** | **高度刻度**（每 0.5 米一道：0.5 / 1.0 / 1.5 / 2.0 m） | **垂直尺。** 量你「跳多高」。**1.0 m 那条是橙色的** —— 因为「跳不跳得过一米」是这里唯一的关键判断（见第 13 节） |
| 北墙门洞旁那两根**橙色竖条** | **门框标记** | 门洞的边缘位置。它标的是「可行动方向」—— 不是装饰 |
| 面板里那 **25 根横条** | **滑条** | 每一个 = 一个手感参数。往右拖 = 值变大 |
| 滑条右边的**数字** | 当前值 | 实时值，不是目标值 |
| 面板底部**三行字** | **读数** | 仪表。不是给你调的东西，是给你判断的 |
| 面板底下**三个按钮** | **存快照 / 取快照 / 恢复默认** | 见 12.3 —— 这是「改动会不会丢」的答案 |

**判据**：不是「屏幕上有几个条」，而是 —— 你改一个数字之后，**能不能从这些条上看出它生效了**。看不出来，那个参数就是不可调的。

## 5. 靶子 vs 敌人 —— 一次顺序修正（2026-10-12）

**你的原话：**「移动什么的都是服务于砍杀的，是不是先做个敌人再做个武器出来我好知道打起来爽不爽。」

**对的那一半：** 完全对。移动不是战斗的前置，**移动是战斗的一部分**。在一个空房间里拖滑条，你没有可失去的东西 —— 也就分不出「这个身体听我的话」和「这个身体只是没被我用来做任何事」。所以靶子必须在移动调参之前就位。这是对 M1 原设计的修正。

**要改的那一半：** 顺序不是「敌人 → 武器」，而是：

```
靶子（静态，但会反应）
   ↓
武器（挥砍 + 反馈）
   ↓
移动参数 ← 到这一步才有意义
   ↓
敌人 AI（M3）
   ↓
断肢 / 移植（M4）
```

**为什么 AI 排在最后：** 「爽不爽」的变量只有三个 —— ① 挥击窗口对不对 ② 反馈够不够 ③ 目标有没有反应。一个会移动、会反击、会绕后的目标，会往里面塞进第四个变量（AI 行为）。于是你测出「不爽」的时候，分不清是哪一个坏了。**先把三个已知变量调定，再引入第四个。**

**所以靶子刻意了什么都不做：** 不移动、不攻击、不躲闪、不用导航。它只有一件事：**被打，然后有反应**（后仰 + 闪白 + 倒地）。

**代价你要知道：** 静态靶子测不出「追着移动目标砍」。那正是移动参数（`steer_rate_deg`、`deceleration`）真正要吃紧的地方，也是 M3 一到位就会立刻暴露的东西。**这不影响现在该做的事** —— 现在要的是基线，不是全貌。

## 6. M3–M7 → Godot 实现细节

### M3 · 一种敌人

**动哪里：** 复制 `target_dummy.gd` → `scripts/enemy.gd`（改 `CharacterBody3D`）+ 状态枚举。

```
IDLE → APPROACH → WINDUP → ATTACK → RECOVER → (受击) STAGGER → (重击) DOWN
```

**两个取舍：**
- **先别上 NavigationRegion3D。** 房间是空的，`(player.position - position)` 归一化后直线追就够。省掉一整套导航系统，也省掉一堆「怪物卡在门框上」的 bug。
- **可读性 > 聪明。** `WINDUP` 必须长到玩家能用眼角看见。你 v0.2 写「敌人必须主动施压」，但更前置的是：**压力必须看得见**。攻击前的收势、声音、姿势变化，至少给两样。

**派活话术：**
> 为一个 Godot 4 的 CharacterBody3D 敌人实现状态机：IDLE / APPROACH / WINDUP / ATTACK / RECOVER / STAGGER / DOWN。每个状态的进入条件、持续时长、可被哪些事件打断，先用 @export 暴露时长参数。不做寻路导航，只做直线接近 + 保持距离。不做伤害数值，只输出状态切换的时间戳日志。

**验收补一条：** 敌人第一次攻击你之前，你**看见了**它要攻击。看不见，WINDUP 就等于没有。

### M4 · 切断与断肢

**动哪里：** 新增 `scripts/detachable_part.gd`（`RigidBody3D`）；敌人模型上放 `Marker3D` 命名 `arm_l / arm_r / leg_l / leg_r`，每个挂一份独立的碰撞体。

**在 M2 已经给你留好了接口：** `TargetDummy.take_hit(info: Dictionary)` 收的就是字典，M4 直接往里加 `part_name` 和 `impulse` 两个键，**不用改任何调用方**。

**切断流程（四步，不要合并）：**
1. 命中该区域且冲量超过阈值 → 把该 Marker 下的 `MeshInstance3D` 从敌人身上摘掉
2. 在原地实例化一个 `RigidBody3D`，把摘下来的网格塞进去
3. 给它一个沿攻击方向的初始线速度
4. 把部位名写进敌人的 `disabled_parts` 数组 → 状态机读它，缺 `arm_r` 就禁掉那套攻击

**这就是你 v0.2 写在 3.1 的「预设切断点」的全部实现** —— 没有网格切割，没有布尔运算，只有「摘掉、换一个物体、记一个标记」。它便宜，而且它足够。

**派活话术：**
> 在 Godot 4 中实现预设断肢：敌人身上若干部位各有独立命中区域，命中且冲量超阈值时，把该部位的 MeshInstance3D 从敌人节点摘下，创建一个 RigidBody3D 接管这个网格并赋予沿攻击方向的初速度，同时把部位名加入敌人的 disabled_parts。要求断开阈值用 @export 暴露，并要求敌人其它系统能读到 disabled_parts。不做网格切割，不做血液特效。

**你必须亲手做的验收：** 切断后**把视线移开**，只看画面边缘 + 听声音，判断你是否知道它「少了什么」。判断不出，说明断肢现在只是特效，不是系统 —— 而你原则 3 写的正是「系统产生后果」。

### M5 · 环境交互

**只做一种组合：** 一扇门 + 一个凹槽。把断肢放进凹槽 → 门开。

**统一交互规则（对应你 3.2）：** 新增 `scripts/interactable.gd`，每个可交互物上写 `supported_actions: Array[String]`。刀、断肢、门锁、线缆都实现同一个接口，但**各自只开放合乎结构的行为**。

> 关键取舍：不要让所有物体变成同一套可交互物。宁可 5 个物体各支持 1–2 种行为，也不要 1 个物体支持 20 种。前者玩家能形成稳定预期，后者会让人觉得「这游戏到处都是 bug」。

### M6 · 镜子复活

**动哪里：** `scripts/checkpoint.gd`（`Area3D`）+ `main.gd` 里加一个 `reset_level()`。

**按你 v0.2 的取向实现（整个房间重置，不保存复杂状态）：**
最省事的做法是**把房间 / 玩家 / 靶子 / 敌人全放进一个 `Node3D "Level"`**，复活时 `queue_free()` 整个 Level 再重建一次。一行代码换掉一整套状态序列化 —— 在原型阶段这是绝对正确的交易。

**派活话术：**

## 11. 三条报错的修复记录（2026-10-13）

### 11.1 转身时「莫名其妙的左右位移」

**先给结论：这不是代码错误，这就是你在 10-12 要的第 3 条「急转 → 被甩出去」。**

自检实测（冲刺 8.5 m/s、原地转 90°）：

```
+ 1 帧  速度方向偏差 78.0°  横向 -0.139 m
+ 4 帧  速度方向偏差 42.0°  横向 -0.477 m
+ 8 帧  速度方向偏差  0.0°  横向 -0.607 m   ← 收住了
```

偏差角严格以 12°/帧（＝720°/秒）收敛到 0 —— **数学没错，是参数。**

**为什么它读起来「莫名其妙」而不是「有重量」**：视角是**瞬间**跟着鼠标转的（相机焊在身体上），速度方向却是**慢慢**追的。第一人称看不见自己的身体，所以同一件事读起来不是「我的身体有惯性」，而是「世界莫名往旁边滑」。**可见与不可见的错配，才是「莫名其妙」的来源。**

**做了三件事：**

1. **默认值 720 → 2400。** 漂移从 0.607 m 降到 0.133 m，3 帧对齐 —— 手感上等于「指哪走哪」。
   为什么改：本项目已定下的规则是 **M1–M3 身体必须听话，M4 之后才引入别扭**（见 `m1-pre-registration.md`）。0.6 米的横滑是 M4 该做的事，不是基线该有的。
   **想现在就要那个手感？把滑条拖回 720 以下，一次拖动就能回来。**
2. **新增读数「方向偏差 N°」**（＝速度方向与朝向的夹角）。0° = 听话，转身时瞬间飚到 90~180° 再回落。
   这才是「莫名其妙」的解药：**它把不可见的量变成了可读的数字。** M4 判断「身体是不是开始不听话了」，也全靠这个读数。
3. **新增滑条 `turn_speed_keep`（默认 1.0 = 关闭）。**
   原地转身时速度方向会分开但速度**不减** —— 那不是有重量，是**磁悬浮侧滑**。拖到 0.5，急转会明显掉速。
   ⚠️ 实测发现它与 `steer_rate_deg` 耦合：转向 2400 时 3 帧就转完，这个参数几乎没发挥空间。**想用它，先把转向拖低。**

**⚠️ 这一条我没有替你选。** 你 10-12 要它，10-13 说它是 bug —— 两个要求互相矛盾，只有你知道现在要哪个。已经把三个数字和各自的漂移量列在 4.5，滑条上 30 秒就能分辨。

### 11.2 靶子被击杀后无法重新生成

**先说个意外结论：`respawn()` 和 R 键本身都是好的**（自检：按 R 之后 hp=6、down=false）。所以「无法再生」另有原因，一共三条：

| 原因 | 真 bug？ | 修复 |
|---|---|---|
| **屏幕上从没写过 R 是什么键** —— 只有终端启动时打印过一行，不跑终端就看不到 | 是（可用性） | 写进面板提示行：`R 复位靶子` |
| **一个练习靶本来就该自己站起来**，而不是等你按 R | 是（设计缺口） | 新增 `auto_respawn_delay`，默认 **2.5 秒**，面板可调 0–10 |
| **倒地后碰撞体没关** —— 自检抓到 `碰撞disabled=false`。视觉躺下了，碰撞胶囊还立着 → 一根看不见的柱子把你撞停 | **是（真 bug）** | `_fall()` 里连碰撞一起关；`respawn()` 按 `_active` 状态恢复 |

第三条是这次最有价值的一个发现：**它和 `set_active()` 当初犯的错是同一个错**（只改视觉、不改碰撞）。这类错误的特征是「不报错、但你会撞到空气」。

### 11.3 左侧滑条栏显示不完整、无法上下滑动

**原因（数字）**：19 根滑条，原来是「标签一行 + 滑条一行」的竖排，需要 **958 px** 高，从 y=24 开始 → 底部 **982 px**，而窗口只有 **900 px**。溢出 82 px，而且**没有滚动容器** → 最下面两行永远调不到（包括那条最重要的读数）。

**三处修复：**

1. **标签 + 滑条 + 数值压到同一行** → 滑条区从 958 px 降到 **431 px**
2. **滑条区套 `ScrollContainer`** → 参数再加也不会掉出屏幕（M4 断肢还要加一批）
3. **面板高度每次窗口变化时重算**，永远不超过视口；标题和底部读数**不进滚动区**（读数是仪表，不能滚走）

**修复后实测**：19 行 · 固定部分 129 px + 滑条区 431 px + 边距 = **合计 592 px**，900 px 窗口 **余 308 px**。

### 11.4 本次的验证

## 12. 三条修复记录（2026-10-14）

### 12.1 看着砍到了，却经常判不到

**先量化。** 自检读出的两组数字：

```
刀身：中心距手腕 0.660 m，全长 1.150 m  →  刀尖 1.235 / 刀根 0.085
命中形状：球半径 0.420 m，球心在刀身中点 0.660 m  →  检测最远 1.080 m
缺口：刀尖 1.235 − 检测最远 1.080 = 0.155 m 判不到
```

**根因不是「长度写错了」，是「形状用错了」。**

旧实现是一个 **半径 0.42 的球，球心走在刀身中点**上。这带来两个方向相反的错误：

| 方向 | 视觉 | 检测 | 结果 |
|---|---|---|---|
| **沿刀身（长度）** | 刀尖 1.235 m | 球心 0.660 + 半径 0.420 = **1.080 m** | **尖端 15.5 cm 是断的** → 「看着砍到了却判不到」 |
| **垂直刀身（宽度）** | 刀刃厚 0.085 m | 球直径 **0.840 m** | **宽了约 10 倍** → 隔空砍中 |

所以你同时有两个 bug，而只有「够不着」那个被你感觉到了 —— 因为「隔空砍中」在打一个大靶子时几乎看不出来。

**边界实测（同一套自检脚本，改前 / 改后）：**

| 靶子距离 D | 旧实现 | 新实现 |
|---|---|---|
| 1.0 m | 命中 ✓ | 命中 ✓ |
| 1.3 m | 命中 ✓ | 命中 ✓ |
| **1.6 m** | **未命中 ✗** | **命中 ✓** |
| 1.9 m | 未命中 ✗ | 未命中 ✗ |
| 2.2 m | 未命中 ✗ | 未命中 ✗ |

有效距离整体推后了约 0.3 m，**缺口消失**。

**修法（三步）：**

1. **形状换成沿刀身的胶囊**（`CapsuleShape3D`），不再是球。
2. **长度从 Blade 网格的 `size` 读出来**，注入给武器 —— 不再手填。
   于是「模型改了但碰撞箱没改」在**结构上**不可能再发生，因为碰撞箱是**从模型算出来的**：
   ```
   reach = 刀身中点 + 刀身长 × 0.5 + 刀刃容错
   ```
   自检断言：`reach − visual_tip == blade_radius`（实测 0.0700 = 0.0700 ✓）。
3. **新增滑条 `刀刃容错 radius m`**（默认 0.07 = 横向总宽 14 cm）。这是「擦到算不算中」的唯一旋钮：
   往下拖（0.02）只认真正的刀刃，手感很硬；往上拖（0.20）开始隔空砍中。

**顺手修掉的一个隐患**：旧 `_detect()` 里写了
```gdscript
_shapecast.global_transform = Transform3D(Basis(), _prev_mid)
```
它会把形状的旋转重置成 identity。以前形状是**球**，球没有朝向，所以看不出问题；换成胶囊之后，那样写会让胶囊**永远竖着** —— 等于又错一次。现在改成不动节点、只把世界位移转进局部空间（`target_position` 是局部坐标）。

### 12.2 跳跃速度默认一直是 0

**结论：这是刻意的，不是坏了。** 代码注释里写着理由 —— v0.2 计划书里**没有跳跃**。

但你的困惑是合理的，而且**责任在我**。真正的问题是三条叠在一起：

### 13.1 先说那个被推翻的判断

我上一轮把跳跃默认关掉了，理由是「它是手感三变量之外的第四个变量」。**这个归类是错的。**

| | 挥砍的那三个变量 | 跳跃 |
|---|---|---|
| 属于 | **战斗**系统 | **移动**系统 |
| 和谁竞争 | 挥击窗口 / 反馈 / 目标反应 | `walk_speed` / `steer_rate` / `deceleration` |

移动变量和战斗变量**不竞争**。跳跃和 `walk_speed` 才是一类东西 —— 它属于 M1 的地盘，不是 M2 的入侵。所以 `jump_velocity` 默认从 `0` 改成 **`7.0`**（跳高约 1.02 m）。

> ⚠️ 你的存档里已经是 **`6.7`**（跳高约 0.94 m）—— 那是你自己拖的。
> **存档优先于代码默认值**，所以打开还是 6.7。想试 7.0 就拖一格。

### 13.2 「一点进去就想跳」到底是什么意思

它**不是**「跳跃很爽」的证据，是**对空间操控权的第一反应** —— 一个人进到一个新空间，第一件事是测试「这里能被怎么玩」。跳跃是这套测试里最便宜的那一下。

但它是真的需求，所以默认开。

### 13.3 它立刻撞上的那个冲突（这才是要你去测的）

| 位置 | 刀身中点离地 |
|---|---|
| 站着 | **1.430 m** |
| 跳到最高点 | **2.423 m** |
| 靶子全高 | 2.000 m |

**跳到最高点时，刀高出靶子头顶 0.423 m。**

⇒ **跳起来平视挥刀会砍空，必须低头才砍得到。**

这不是 bug，这是「跳跃 × 近战」的第一个真实交点。接下来要判断的事是：刀的高度跟着视角走（低头砍低处 / 抬头砍高处），这个操作成本和它换来的空间感，哪个更值。

### 13.4 新增：垂直尺

地面刻度线量的是「你走多远」，量不了「你跳多高」。所以东西两墙各加了四条横线：**0.5 / 1.0 / 1.5 / 2.0 m**，**1.0 m 那条用门框的橙色**。

理由和地面刻度线完全一样：**把不可见的量变成可读的参照。** 没有垂直的尺子，拖 `jump_velocity` 仍然是在盲调 —— 你分不清「我改了」和「我以为我改了」。

面板读数同步：`跳高 1.02 m · 实测 0.98` —— 左边是公式，右边是你刚才真的跳了多高。

### 13.5 本次的验证

| 检查 | 结果 |
|---|---|
| 高度刻度生成 | 8 条（4 个高度 × 东/西两墙）✓ |
| 理论 vs 实测 | 理论 0.935 m · 实测 **0.992 m** · 差 +0.057 m（物理积分离散误差，正常）✓ |
| `last_jump_peak()` | 0.992 m，与自检独立测得的峰值一致 ✓ |
| 刀高（站 / 跳） | 1.430 m → 2.423 m，超出靶子顶 **0.423 m** ✓ |
| 空跑 | `--headless --quit-after 600` 零运行时错误 ✓ |

**过程中我自己修的一个 bug（值得记）**：腾空高度的基准 y 原本写成「离地那一刻才记」，结果取到了起跳后第一帧（已经上升约 0.11 m），实测值就系统性少报整整一帧。表现是「面板说跳了 0.88，其实跳了 0.99」—— 不报错、不崩溃，只是数字一直偏一点。**这类错误最难发现，因为它看起来完全正常。**

## 14. 屠刀换型 + 三个新需求的分诊（2026-10-14 夜）

用户一次提了三件事：

| # | 需求 | 本轮 |
|---|---|---|
| 1 | 武器做成 **M&B / For Honor 那种四向操作**，但**不要刺击**（拿的是屠刀） | **不做**，见 14.3 |
| 2 | **武器换成屠刀原型** | ✅ **做了** |
| 3 | **腿部攻击 / 飞踢**（按一个键起跳踢出，威力 ∝ 初速度） | **不做**，见 14.4 |

### 14.1 屠刀换了什么

改的是 `main.gd` 里那**一个** `BLADE_SIZE` 常量，加上 `_build_weapon()` 里两行新网格。

| | 旧（直刀） | 新（屠刀） |
|---|---|---|
| 刀身 `BLADE_SIZE` | `0.085 × 0.028 × 1.15` | **`0.040 × 0.165 × 0.80`** |
| 刀身朝向 | **平躺**（宽 0.085 沿左右，厚 0.028 沿上下） | **竖立**（厚 0.040 沿左右，**宽 0.165 沿上下**） |
| 刀背 / 刃口 | 没有 | **两条特征部位**：背脊（更厚 0.056）在上缘，刃口（更薄 0.014、近白色）在下缘 |
| 护手 | 十字护手 `0.24 × 0.05 × 0.05` | 改成小块**挡片** `0.062 × 0.10 × 0.035` |
| 柄 | 0.05 见方、长 0.22 | 更粗、**长 0.30**（能双手攥） |
| 臂展（距手腕） | 1.305 m（含你存档的 `blade_radius 0.125`） | **1.010 m** |
| 相机 → 刀尖 水平距离 | 约 1.34 m | **1.049 m** |

⚠️ **这是唯一会改变玩法的一条：屠刀短了 0.30 m，你得贴得更近才能砍到。** 刻意的 —— 屠刀是重工具，不是长剑。嫌短就把 `0.80` 调大，模型和判定会一起变。

### 14.2 为什么刀身要「竖起来」+ 单边开刃

这两件事都不是为了好看，是**为四向攻击铺路**：

- 刀平躺的时候，你从上往下只看得到一条细线 —— **看不出刃在哪一边**；
- 竖起来 + 上背下刃之后，**刀的形状本身就是方向指示器**：哪边厚、哪边薄、刃朝着谁，一眼可辨；
- 而「刃在哪一边」是四向攻击**能不能成立**的前提 —— 如果玩家连自己的刀现在朝哪，四向就只是四个不同的动画而已（详见 14.3）。

这一层是**免费**的：屠刀在现实里本来就是单边开刃。

### 14.3 四向攻击：为什么现在不做（**这一节最重要**）

先把参照查清楚了。M&B、For Honor、Kingdom Come: Deliverance 三家的资料都指向同一件事：

> **四向攻击的对手不是「挥砍」，是「格挡」。**

KCD 的原话（已核实）：六向 = 上劈 / 右横 / 左横 / 右下上撩 / 左下上撩 / 中刺，**鼠标移动方向同时决定你的攻击方向和你的格挡方向**，而**对手用的是同一套系统** ——
「combat 里最关键的一部分，是不断观察对手的姿态，预判他这一刀会从哪来，好用同方向的格挡去接。」

也就是说，四向系统在**一个人对着靶子挥**的时候是不存在的。它需要一个**也会用四个方向打你、并且会读你方向**的对手。

**在你这个项目里，四向只有两个价值，而且现在都拿不到：**

| 价值 | 需要什么 | 什么时候有 |
|---|---|---|
| **猜拳** —— 你猜他要砍哪、他要猜你砍哪 | 会**格挡**、会**攻击**、**方向可读**的敌人 | **M3 之后** |
| **部位选择** —— 上劈打头、横扫打手、下劈打腿 | 靶子**分部位**（头/手/腿各自结算） | **M4 断肢** |

⇒ 所以现在做四向，你会得到一个**四档动画播放器**：四个动作看起来不同，玩起来完全一样。而它会给你增加四个变量，让「砍中那一下爽不爽」这个问题**彻底失去可诊断性**。

**第一人称的障碍在哪（顺带说清，免得以后绕弯路）：**
不是「第一人称做不了」—— **KCD 就是第一人称做的**。真正的障碍是**你看不见自己的刀**，所以看不见「我现在朝哪个方向」。KCD 的解法是在屏幕中心放一个**方向指示器（combat rose）**。
而 14.2 做的那两件事，给了你一条更省的路：**把指示器做成刀本身。**

**如果哪天要做，唯一需要的机制只有一个**：怎么让鼠标同时干「转视角」和「选方向」这两件事。KCD 用的是「鼠标累计位移方向」。这是那一轮真正要解决的问题，不是加四个动画。

### 14.4 飞踢：有现成样本，但先别做

你这个想法有先例，而且先例里的做法和你说的**几乎一致**。

KCD 的踢（已核实）：
- 键位是**独立的一个键 F**，归类「特殊攻击 / Kick」
- 消耗大量耐力，**大约 3 秒**执行
- 命中后让对手**失衡**
- 它的用途是**绕过对手的格挡**
- **代价**：执行期间你**极度暴露**，而且不能中途停下改去格挡

你的版本（威力 ∝ 初速度）比 KCD 那版更省：**不需要额外的按键去区分「原地踢」和「飞踢」——同一个键，物理速度自然分开。**

但它缺一件东西：**代价**。如果踢没有代价，玩家会一直踢 —— 那它就是零成本的最优解，四向和挥砍都会失去意义。KCD 用「3 秒硬直 + 暴露」来平衡。你需要一个同类的代价。

**键位建议：F**（KCD 同款，而且你的 F 现在还空着 —— 现在用的是 WASD / Shift / 空格 / 左键 / Tab / R / Esc）。

**为什么建议排在四向前面**：踢的对手是**空间和距离**，不是敌人的 AI —— 所以它**现在就能被验证**（跑起来踢靶子、静止踢靶子，看差别）。而四向必须等敌人。

### 14.5 三件事的顺序（我建议的，你可以推翻）

> **屠刀（已做）→ 飞踢（下一步）→ 四向（等 M3 有敌人）**

理由不是「哪个更有用」，是**每一件都是前一件的结果自然要求的**：

1. **屠刀变短了** → 你得贴上去打 → 「贴上去」这个动作本身就在要求一个「推开 / 踹开」的手段（**这就是踢的动机**）；
2. **短武器 + 踢是互补的**：够不着的时候踢一脚，把对方踹开或者踹失衡；
3. **而踢要成为有意义的「另一种选择」，前提是它和砍不一样** —— 砍是固定方向，踢是「往你面朝的方向」，这个区别要等**四向**才真正成立（四向让「方向」这件事对玩家有意义）。

而四向排最后，是因为**它是唯一一个「现在做了也测不出东西」的**。

## 15. 三条实测反馈的修复（2026-10-14 深夜）

用户实机跑过第一版屠刀之后报的三条。**三条全部成立，而且各有各的根因。**

> ⚠️ 第 14 节 14.1 里那张表是**第一版屠刀**的数据，已被本节取代。第一版屠刀的问题就是本节 15.1。

| # | 他报的 | 是真 bug 吗 | 根因 |
|---|---|---|---|
| 1 | 武器建模跟屠刀几乎没有关系 | 是（比例 + 姿态） | **长高比 4.8:1**，且刀面侧对镜头 |
| 2 | 挥砍很怪，只有左右砍 | 是（两个根因） | ① 没有下压分量 ② 旋转中心在手腕上 |
| 3 | 空中还能自由左右前后移动 | 是（设计缺口） | 地面和空中用了同一套操控规则 |

### 15.1 问题一：「这根本不是屠刀」——三个原因，主因是比例

改之前那把刀：`0.040 厚 × 0.165 高 × 0.80 长`。

**根因是长高比。** 0.80 ÷ 0.165 = **4.8 : 1** —— 那是砍刀的轮廓。真实屠刀在 **1.8 : 1** 上下：短、高、方。

但只改比例还不够，另外两件事同时在拖后腿：

| # | 问题 | 后果 |
|---|---|---|
| ① | **长高比 4.8:1** | 看到的是一块长条铁板。**这是主因** |
| ② | **手长在脸上** —— 手腕只在眼前 0.12 m 处 | 刀像从脸旁边长出来的，不像「被手拿着」 |
| ③ | **刀面朝向** | 见下 |

**③ 这一条要单独说清楚，因为它最容易搞反。**

「刀面看不看得见」是可以算的：把刀面法线和「手腕 → 镜头」的方向做夹角。
- **0° = 刀面正对镜头**，屠刀有多宽一目了然；
- **90° = 刀面侧对镜头**，你只剩刀背那 3 厘米厚度可看。

而这三件事会**互相打架**：

| 版本 | 手腕位置 | 刀面偏角 |
|---|---|---|
| 旧直刀 | 眼前 0.12 m / 右侧 0.30 m | 40.3° |
| 第一版屠刀 | 同上 | 40.3° |
| **只修①②、不动 roll**（假想） | 眼前 0.42 m | **61.8° ❌ 更差** |
| **当前（①②③ 一起修）** | 眼前 0.42 m | **34.5° ✓** |

看第 3 行：**把手往前伸（修②）会让刀面反而更侧对镜头。** 所以「把刀面转过来」（roll）不是锦上添花 —— 它是修②的必要配套。这三项必须一起改，改两项会更糟。

**修法：**

| 项 | 旧 | 新 |
|---|---|---|
| `BLADE_SIZE` | `0.040 × 0.165 × 0.80` | **`0.032 × 0.22 × 0.40`**（长高比 1.82） |
| 手腕位置 | 相对头 `(0.30, -0.22, -0.12)` | **肩膀 `(0.17,-0.38,0.02)` + 手腕 `(0.10,0.10,-0.44)`** |
| 持刀姿态 | 无（`rotation = (0, swing, 0)`） | **新增 `hold_roll/pitch/yaw`，默认 `(-45°, 8°, 10°)`** |
| 柄 | 长 0.22 | 长 0.26 + **柄尾配重块** |
| 刀尖距眼 | 约 1.07 m | **0.958 m** |

> ⚠️ **注意读数口径换了。** 以前那一行叫「臂展」，是**从手腕**量的（1.01 m）；
> 现在叫「刀尖距眼」，是**从眼睛**量的（0.958 m）。
> 换口径的理由：手腕自己也在被挥砍带着绕肩膀转，从手腕量会少算一截 ——
> 而玩家感知到的距离永远是「刀尖离我的眼睛多远」。

### 15.2 问题二：「只有左右砍、动作很怪」——两个根因

**根因 A：挥击只有一个平面。**

改之前的代码是 `_pivot.rotation.y = _swing_angle()` —— 只有 yaw。
yaw 是**绕竖轴转**，所以刀永远在**一个水平面里**扫过去。那不是挥砍，那是「画面里横着划过一根铁条」。

**修法：新增 `swing_tilt_deg`（挥击倾斜）。** 一次挥砍用同一个归一化进度 `s ∈ [-1, +1]` 同时驱动两个分量：

```
yaw   =  s × 半个扫掠角    → 横向扫过 110°
pitch = -s × 倾斜角        → 从+30° 压到 -30°（右上 → 左下）
```

- `tilt = 0` → 纯横扫（**就是改之前的行为，拖回去就能对比**）
- `tilt = 30` → 斜劈（**默认。屠刀真实的用法**）
- `tilt = 90` → 纯下劈

**为什么 pitch 要跟着 s 走、而不是单独做一段抬手动画：因为一次挥砍只有一个动作。** 抬手和劈下是同一个弧的两端；分成两段写，中间一定会在某一帧对不上，看起来就是「抖了一下」。

实测：有效窗口内刀尖从 **1.887 m 落到 0.950 m，落差 0.937 m**。

**根因 B：旋转中心挂错了地方。**

改之前旋转直接加在**手腕**上 → 刀绕着手腕**原地翻**，手腕一动不动。
真实的挥砍是**整条手臂绕肩膀转**，手腕自己也在走一条弧线。

这个差别肉眼读出来就是：
- 绕手腕转 → 「刀被钉在脸上转了一下」
- 绕肩膀转 → 「抡出去了」

**修法：节点拆成两级。**

```
Weapon
└── Swing   （肩膀）← 挥砍的旋转施加在这里，位置固定
    └── Pivot（手腕）← 位置固定，只管静止持刀姿态
        ├── Handle / Butt / Collar
        ├── Blade / Spine / Edge
        ├── BladeMid
        └── ShapeCast3D
```

> **「姿态」和「动作」是两个节点上的两件事。** 混在一个节点上写，你就会在调姿态时把动作一起改掉。

### 15.3 问题三：空中还能自由移动 —— 这是真的「喷气背包」

改之前的写法对地面和空中**一视同仁**。于是跳起来之后你还能像站在地上一样改向 —— 那不是跳跃，那是喷气背包：**它把「跳」这个动作的后果抹掉了**（起跳的方向、速度、时机全部不再重要）。

**修法：新增 `air_control`（默认 0.0）。**

它同时管三件事 —— 因为它们本来就是同一件事：**你在空中还剩多少操控权。**

| | 地面 | 空中 |
|---|---|---|
| 加速 | 满 | `× air_control` |
| 转向 | 满 | `× air_control` |
| **松手减速** | 有摩擦，会停 | **完全没有** |

**「空中不减速」这一条要单独说：** 空中没有摩擦，所以松开按键时水平速度**原样保留**。这不是物理洁癖 —— 如果空中会掉速，你一松手就在空中急刹车，那正是你要去掉的喷气背包的**镜像版本**，一样假。

**它和跳跃的分工：**

> `jump_velocity` 决定**跳多高**；`air_control` 决定**跳出去之后还听不听话**。
> 前者是空间，后者是操控权。**两个都要有，跳跃才是一次「有后果的动作」。**

**这一项同时是后期那些位移技能的插口。** 二段跳、冲刺、喷气、滑翔 —— 它们全都是「在特定条件下把 `air_control` 临时拉高」。所以现在把它做成一个**参数**而不是写死 0，是有意的：将来加技能改的是**这个数**，不用重写移动逻辑。

**参照**：黑魂那一类游戏的跳跃接近 0 空中操控（你被锁在弹道上）；Quake 那一类的空气操控是核心玩法。**两种都对，看你要哪个游戏。**

### 15.4 本次的验证

自检 **10 项通过 · 0 失败**（脚本已删）：

| 检查 | 结果 |
|---|---|
| 屠刀比例 | 0.400 长 × 0.220 高 × 0.032 厚 → **长高比 1.82**（改前 4.8） |
| 碰撞箱 = 模型的函数 | reach 0.635 − 刀尖 0.510 = **0.125** = 你的容错半径 ✓ |
| **刀面朝向镜头** | **34.5°**（< 45° 才看得清刀面；不动 roll 会是 61.8°） |
| 刀尖距眼 | **0.958 m** |
| **挥击有下压分量** | 有效窗口内刀尖 **1.887 → 0.950 m，落差 0.937 m** |
| 挥击横向扫过 | 肩膀 yaw **-55° → 55°**（110°） |
| **air_control=0：无法改向** | 按住 W 飞 22 帧，方向只偏 **0.00°** |
| **air_control=0：不掉速** | 速度 **4.533 → 4.533** |
| air_control=1：对照组 | 同样飞 22 帧，方向偏 **90.0°**（= 那个喷气背包） |
| **一次挥击只结算一次** | 挥一刀，命中 **+1**；靶子 HP 5/6 |

**自检时踩的坑（值得记）：** 第一版测试把「按下按键之后 3 帧」当采样基准 —— 而对照组在这 3 帧里已经把 90° 转完了，于是「转向幅度」测出来是 0，对照组反而 FAIL。
**基准必须取在「按下按键的同一帧」。** 这类错误不报错，只会让你拿到一个反过来的结论。

### 15.5 你可以自己验的三条（当场就能做）

1. **刀面** → 打开面板，把 `│ 持刀翻转 roll °` 拖到 **0**：刀面侧过去，你只剩刀背那条厚度可看。拖回 **-45**：屠刀那个「宽而薄的矩形」回来了。**盯读数「刀面偏角」**，它会从 34° 变到 62° 左右。
2. **挥击形状** → 把 `│ 挥击倾斜 tilt °` 拖到 **0**：变回你抱怨的那个「只有左右砍」。**30** 是斜劈，**80** 几乎是直上直下地砸。一次只动这一根。
3. **空中** → 助跑、按空格跳出去、在空中按住 W：**改不了向，也停不下来**。然后把 `air_control  空中操控` 拖到 **1**，再跳一次 —— 那个能自由飘的版本回来了。**这两个之间就是你要的那个值。**
