## 3. 怎么跑（别跳）

1. Godot → Import → 选 `project.godot` → Import & Edit
2. F5
3. **先别动。** 锁定鼠标（点一下画面）
4. WASD 走一圈，按住 Shift 冲刺，**注意地上的刻度线**
5. **鼠标左键 挥砍。** 两个靶子：左手边近靶（1 米），右手边远靶（4 米）
6. Tab 开关面板 · R 复位靶子 · Esc 释放鼠标

> 面板最后一行有两组数字，那是你的验收工具：
> **「挥击 N · 命中 M」**。一次挥击打五下这个 bug 会在这里现形，不用靠眼睛。
> 旁边「靶子 6/6 · 6/6」是剩余血量。

## 5. 靶子 vs 敌人 —— 一次顺序修正（2026-10-12）

**你的原话：**「移动什么的都是服务于砍杀的，是不是先做个敌人再做个武器出来我好知道打起来爽不爽。」

**对的那一半：** 完全对。移动不是战斗的前置，**移动是战斗的一部分**。在一个空房间里拖滑条，你没有可失去的东西 —— 也就分不出「这个身体听我的话」和「这个身体只是没被我用来做任何事」。所以靶子必须在移动调参之前就位。这是对 M1 原设计的修正。

**要改的那一半：** 顺序不是「敌人 → 武器」，而是：

```
靶子（静态，但会反应）
   ↓
武器（挥砍 + 反馈）
   ↓
移动参数 ← 到这一步才有意义
   ↓
敌人 AI（M3）
   ↓
断肢 / 移植（M4）
```

**为什么 AI 排在最后：** 「爽不爽」的变量只有三个 —— ① 挥击窗口对不对 ② 反馈够不够 ③ 目标有没有反应。一个会移动、会反击、会绕后的目标，会往里面塞进第四个变量（AI 行为）。于是你测出「不爽」的时候，分不清是哪一个坏了。**先把三个已知变量调定，再引入第四个。**

**所以靶子刻意了什么都不做：** 不移动、不攻击、不躲闪、不用导航。它只有一件事：**被打，然后有反应**（后仰 + 闪白 + 倒地）。

**代价你要知道：** 静态靶子测不出「追着移动目标砍」。那正是移动参数（`steer_rate_deg`、`deceleration`）真正要吃紧的地方，也是 M3 一到位就会立刻暴露的东西。**这不影响现在该做的事** —— 现在要的是基线，不是全貌。

## 6. M3–M7 → Godot 实现细节

### M3 · 一种敌人

**动哪里：** 复制 `target_dummy.gd` → `scripts/enemy.gd`（改 `CharacterBody3D`）+ 状态枚举。

```
IDLE → APPROACH → WINDUP → ATTACK → RECOVER → (受击) STAGGER → (重击) DOWN
```

**两个取舍：**
- **先别上 NavigationRegion3D。** 房间是空的，`(player.position - position)` 归一化后直线追就够。省掉一整套导航系统，也省掉一堆「怪物卡在门框上」的 bug。
- **可读性 > 聪明。** `WINDUP` 必须长到玩家能用眼角看见。你 v0.2 写「敌人必须主动施压」，但更前置的是：**压力必须看得见**。攻击前的收势、声音、姿势变化，至少给两样。

**派活话术：**
> 为一个 Godot 4 的 CharacterBody3D 敌人实现状态机：IDLE / APPROACH / WINDUP / ATTACK / RECOVER / STAGGER / DOWN。每个状态的进入条件、持续时长、可被哪些事件打断，先用 @export 暴露时长参数。不做寻路导航，只做直线接近 + 保持距离。不做伤害数值，只输出状态切换的时间戳日志。

**验收补一条：** 敌人第一次攻击你之前，你**看见了**它要攻击。看不见，WINDUP 就等于没有。

---

### M4 · 切断与断肢

**动哪里：** 新增 `scripts/detachable_part.gd`（`RigidBody3D`）；敌人模型上放 `Marker3D` 命名 `arm_l / arm_r / leg_l / leg_r`，每个挂一份独立的碰撞体。

**在 M2 已经给你留好了接口：** `TargetDummy.take_hit(info: Dictionary)` 收的就是字典，M4 直接往里加 `part_name` 和 `impulse` 两个键，**不用改任何调用方**。

**切断流程（四步，不要合并）：**
1. 命中该区域且冲量超过阈值 → 把该 Marker 下的 `MeshInstance3D` 从敌人身上摘掉
2. 在原地实例化一个 `RigidBody3D`，把摘下来的网格塞进去
3. 给它一个沿攻击方向的初始线速度
4. 把部位名写进敌人的 `disabled_parts` 数组 → 状态机读它，缺 `arm_r` 就禁掉那套攻击

**这就是你 v0.2 写在 3.1 的「预设切断点」的全部实现** —— 没有网格切割，没有布尔运算，只有「摘掉、换一个物体、记一个标记」。它便宜，而且它足够。

**派活话术：**
> 在 Godot 4 中实现预设断肢：敌人身上若干部位各有独立命中区域，命中且冲量超阈值时，把该部位的 MeshInstance3D 从敌人节点摘下，创建一个 RigidBody3D 接管这个网格并赋予沿攻击方向的初速度，同时把部位名加入敌人的 disabled_parts。要求断开阈值用 @export 暴露，并要求敌人其它系统能读到 disabled_parts。不做网格切割，不做血液特效。

**你必须亲手做的验收：** 切断后**把视线移开**，只看画面边缘 + 听声音，判断你是否知道它「少了什么」。判断不出，说明断肢现在只是特效，不是系统 —— 而你原则 3 写的正是「系统产生后果」。

---

### M5 · 环境交互

**只做一种组合：** 一扇门 + 一个凹槽。把断肢放进凹槽 → 门开。

**统一交互规则（对应你 3.2）：** 新增 `scripts/interactable.gd`，每个可交互物上写 `supported_actions: Array[String]`。刀、断肢、门锁、线缆都实现同一个接口，但**各自只开放合乎结构的行为**。

> 关键取舍：不要让所有物体变成同一套可交互物。宁可 5 个物体各支持 1–2 种行为，也不要 1 个物体支持 20 种。前者玩家能形成稳定预期，后者会让人觉得「这游戏到处都是 bug」。

---

### M6 · 镜子复活

**动哪里：** `scripts/checkpoint.gd`（`Area3D`）+ `main.gd` 里加一个 `reset_level()`。

**按你 v0.2 的取向实现（整个房间重置，不保存复杂状态）：**
最省事的做法是**把房间 / 玩家 / 靶子 / 敌人全放进一个 `Node3D "Level"`**，复活时 `queue_free()` 整个 Level 再重建一次。一行代码换掉一整套状态序列化 —— 在原型阶段这是绝对正确的交易。

**派活话术：**
> 实现一个 Godot 4 检查点：玩家进入 Area3D 时记录当前检查点；玩家死亡后经过短暂停顿，销毁并重建整个 Level 节点（房间 + 玩家 + 敌人），把玩家放回最近检查点。要求：不保存敌人个体状态，不保存拾取历史；死亡过渡期间冻结输入。实现后列出重置了哪些东西、哪些没有。

## 7. 我给 v0.2 补四条

**第一条：M2 的验收少了「手感」那一整半。**
你写的是「能稳定命中；不会多帧重复结算；切中与挥空有清楚差别」——前两条是**正确性**，第三条是**手感但不可测**。补一条可测的：

> **闭眼（或背对屏幕）时，也能分辨切中与挥空。**

靠音效 + 顿帧 + 屏震。这一条不过，等 M3 之后再补就晚了 —— 因为那时候你已经把「手感差」归因到敌人身上了。

**第二条：M2 的声音钩子是空的，这是刻意的。**
`weapon.gd` 里 `_play_swing_sound()` 和 `_play_hit_sound()` 是两个空函数。它们不是我忘了 —— **声音是《猪人》的签名，属于作者性，不该由 AI 塞占位素材。**
代价是：上面那条「闭眼分辨」的验收，在你填进自己的声音之前**只能靠顿帧和屏震裸考，大概率过不了**。这是设计，不是缺陷。

**第三条：没有版本对照的习惯。**
每天结束两件事，成本 2 分钟：一行 `git commit` + 一段 10 秒录屏存到 `documents/clips/`。它会在第 5 天救你一次。

**第四条：「看不懂的代码不许进项目」。**
你是零代码起步，AI 写的代码**能跑，但不一定对**。硬规矩：

> 任何 AI 交付的脚本，AI 必须同时说清三件事：**它放在哪、它依赖什么、参数在哪改。**
> 说不清，就不要。不是因为优雅 —— 是因为两天后你得自己改它。
