## 1. 本机环境（我已实测）

| 项 | 位置 / 状态 |
|---|---|
| Godot | `D:\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64.exe`（4.7.2 stable） |
| Git | `D:\Git\bin\git.exe`（2.54）—— **还没配 user.name / user.email** |
| 项目 | `D:\wb\2026-10-11-00-52-55\PigMan\`（Godot 项目根目录） |
| 已初始化 | 是，`.gitignore` 已写好（`.godot/` 不进版本库） |

**第一次提交前，先跑这两行（只需一次）：**

```bash
"D:/Git/bin/git.exe" config --global user.name "你的名字"
"D:/Git/bin/git.exe" config --global user.email "你的邮箱"
```

**在哪里敲：** 打开 **Git Bash**（开始菜单搜 `Git Bash`，或双击 `D:\Git\git-bash.exe`），在里面直接写 `git config ...` 就行，不必带上面那串全路径。全路径写法是给 VS Code 终端 / PowerShell 用的（那里 `git` 可能不在 PATH 里，会提示「不是内部或外部命令」）。

**邮箱有个坑，但它不报错：**

- 以后若把项目推到 GitHub，**commit 里的邮箱必须是 GitHub 账号验证过的那个**，否则提交不算到你名下（头像、贡献格子都不显示）。它是**静默失效** —— 等你发现时可能已经几十条提交了。
- 不想公开真实邮箱，就用 GitHub 提供的隐私邮箱 `你的用户名@users.noreply.github.com`。
- 名字同理：提交几十条后再改，要重写历史才能改干净。现在填一次就好。

**可选，但此刻是零成本：** 仓库当前分支叫 `master`（GitHub 现在默认 `main`）。现在还没有任何提交，改名只要一行：

```bash
"D:/Git/bin/git.exe" branch -m main
```

**第一次提交会刷出 CRLF 警告**（`LF will be replaced by CRLF`）—— Windows 换行符提醒，单人项目无影响，不用管。

**打开项目：** 启动 Godot → `Import` → 选 `PigMan\project.godot` → `Import & Edit` → 按 F5。

**已做的验证（不是我"觉得应该没问题"）：**
- `--headless --editor --quit`：五个全局类全部注册成功，零脚本错误
- `--headless --quit-after 180`：连跑 180 帧，零运行时错误

## 3. 第一次怎么跑（5 步，别跳）

1. Godot → Import → 选 `project.godot` → Import & Edit
2. F5
3. **先别动。看那个面板。** 那 9 个滑条就是你的手感控制台
4. 点一下画面锁定鼠标 → WASD 走一圈，按住 Shift 冲刺。**注意地上的刻度线** —— 它们就是给你看速度的
5. Tab 开关面板 · Esc 释放鼠标

> 地上每 2 米一道刻度，是这份骨架里我最想让你注意的东西。
> 没有它，你把 `acceleration` 从 45 拖到 120，眼睛是看不出来的。

## 4. 参数表（M1 的全部滑条）

| 参数 | 默认 | 面板范围 | 它决定什么 | 调参顺序 |
|---|---|---|---|---|
| `walk_speed` | 4.0 | 1–12 | 慢走速度 | **第 1 个动** |
| `acceleration` | 45 | 2–150 | 起步有多「硬」 | 第 2 |
| `deceleration` | 28 | 2–150 | 松手滑多远（惯性） | 第 3 |
| `sprint_speed` | 8.5 | 1–22 | 冲刺有多快 | 第 4 |
| `mouse_sensitivity` | 0.0022 | — | 视角灵敏度（＝计划书的 turn_response） | 第 5 |
| `pitch_limit_deg` | 89 | 30–89 | 抬头 / 低头上限 | 后期 |
| `eye_height` | 1.65 | 1.0–2.2 | 眼睛高度（改身体比例感） | 后期 |
| `gravity` | 24 | 0–60 | 重力 | 用到再调 |
| `jump_velocity` | 0 | 0–12 | 跳跃初速，**默认 0 = 不跳** | 先别开 |

**铁律：一次只动一个滑条。** 同时动两个，你永远不知道是哪个起了作用。

## 5. M2–M7 → Godot 实现细节

### M2 · 一把刀

**动哪里：** 新增 `scripts/weapon.gd` + `scripts/hit_region.gd`；在 `Player/Head` 下加一个 `Node3D "Weapon"`，刀身上挂一个 `Marker3D` 当刀尖。

**核心实现：开窗 + 扫掠，不要用 Area3D 一直开着。**
```
@export var windup := 0.12    # 前摇
@export var active := 0.08    # 有效命中窗口
@export var recovery := 0.25  # 后摇
```
每次挥击分三段计时；只在 `active` 窗口内每帧做一次 `ShapeCast3D` 沿刀身扫掠；用一个字典记录本次挥击已命中的目标 → **天然解决你验收里写的「不会多帧重复结算」**。

**为什么不能靠 Area3D：** `Area3D` 是持续重叠检测，敌人站在刀的范围里会每帧报一次；你会在 M2 花两天修这个 bug。

**派活话术（可直接复制）：**
> 在 Godot 4 里为第一人称近战实现一次挥击。要求：三段计时（前摇 windup / 有效窗口 active / 后摇 recovery），三个值用 @export 暴露；只在 active 窗口内用 ShapeCast3D 沿刀身做扫掠检测；同一次挥击对同一目标只结算一次；命中时输出（目标、命中点、本次挥击的线速度）。不实现伤害数值、不做动画、不做敌人反应。

**你必须亲手做的验收：** 录 10 秒。然后**闭眼**听声音，判断哪一下是切中、哪一下是挥空。分不出来，说明手感还没到 —— 靠画面能分辨不算。

### M3 · 一种敌人

**动哪里：** 新增 `scripts/enemy.gd`（`CharacterBody3D`）+ 状态枚举。

```
IDLE → APPROACH → WINDUP → ATTACK → RECOVER → (受击) STAGGER → (重击) DOWN
```

**两个取舍：**
- **先别上 NavigationRegion3D。** 房间是空的，`(player.position - position)` 归一化后直线追就够。省掉一整套导航系统，也省掉一堆"怪物卡在门框上"的 bug。
- **可读性 > 聪明。** `WINDUP` 必须长到玩家能用眼角看见 —— 你 v0.2 写「敌人必须主动施压」，但更前置的是：**压力必须看得见**。攻击前的收势动作、声音、姿势变化，至少给两样。

**派活话术：**
> 为一个 Godot 4 的 CharacterBody3D 敌人实现状态机：IDLE / APPROACH / WINDUP / ATTACK / RECOVER / STAGGER / DOWN。每个状态的进入条件、持续时长、可被哪些事件打断，先用 @export 暴露时长参数。不做寻路导航，只做直线接近 + 保持距离。不做伤害数值，只输出状态切换的时间戳日志。

---

### M4 · 切断与断肢

**动哪里：** 新增 `scripts/detachable_part.gd`（`RigidBody3D`）；敌人模型上放 `Marker3D` 命名 `arm_l / arm_r / leg_l / leg_r`，每个挂一份 `hit_region.gd`。

**切断流程（四步，不要合并）：**
1. 命中该区域且冲量超过阈值 → 把该 Marker 下的 `MeshInstance3D` 从敌人身上摘掉
2. 在原地实例化一个 `RigidBody3D`，把摘下来的网格塞进去
3. 给它一个沿攻击方向的初始线速度
4. 把部位名写进敌人的 `disabled_parts` 数组 → 状态机读它，缺 `arm_r` 就禁掉那套攻击

**这就是你 v0.2 写在 3.1 的「预设切断点」的全部实现** —— 没有网格切割，没有布尔运算，只有"摘掉、换一个物体、记一个标记"。它便宜，而且它足够。

**派活话术：**
> 在 Godot 4 中实现预设断肢：敌人身上若干部位各有独立命中区域，命中且冲量超阈值时，把该部位的 MeshInstance3D 从敌人节点摘下，创建一个 RigidBody3D 接管这个网格并赋予沿攻击方向的初速度，同时把部位名加入敌人的 disabled_parts。要求断开阈值用 @export 暴露，并要求敌人其它系统能读到 disabled_parts。不做网格切割，不做血液特效。

**你必须亲手做的验收：** 切断后**把视线移开**，只看画面边缘 + 听声音，判断你是否知道它「少了什么」。判断不出，说明断肢现在只是特效，不是系统 —— 而你的原则 3 写的正是"系统产生后果"。

### M5 · 环境交互

**只做一种组合：** 一扇门 + 一个凹槽。把断肢放进凹槽 → 门开。这就是你 v0.2 8.1 第 6 条说的"打斗结果改变环境"的闭环。

**统一交互规则（对应你 3.2）：** 新增 `scripts/interactable.gd`，每个可交互物上写 `supported_actions: Array[String]`。刀、断肢、门锁、线缆都实现同一个接口，但**各自只开放合乎结构的行为**。

> 关键取舍：不要让所有物体变成同一套可交互物。宁可 5 个物体各支持 1–2 种行为，也不要 1 个物体支持 20 种。前者玩家能形成稳定预期，后者会让人觉得"这游戏到处都是 bug"。

---

### M6 · 镜子复活

**动哪里：** `scripts/checkpoint.gd`（`Area3D`）+ `main.gd` 里加一个 `reset_level()`。

**按你 v0.2 的取向实现（整个房间重置，不保存复杂状态）：**
最省事的做法是**把房间和玩家都放进一个 `Node3D "Level"`**，复活时 `queue_free()` 整个 Level 再重建一次。一行代码换掉一整套状态序列化 —— 在原型阶段这是绝对正确的交易。

**派活话术：**
> 实现一个 Godot 4 检查点：玩家进入 Area3D 时记录当前检查点；玩家死亡后经过短暂停顿，销毁并重建整个 Level 节点（房间 + 玩家 + 敌人），把玩家放回最近检查点。要求：不保存敌人个体状态，不保存拾取历史；死亡过渡期间冻结输入。实现后列出重置了哪些东西、哪些没有。

## 6. 我给 v0.2 补三条

**第一条：M2 的验收少了「手感」那一整半。**
你写的是「能稳定命中；不会多帧重复结算；切中与挥空有清楚差别」——前两条是**正确性**，第三条是**手感但不可测**。补一条可测的：

> **闭眼（或背对屏幕）时，也能分辨切中与挥空。**

靠音效 + 顿帧 + 屏震。这一条不过，等 M3 之后再补就晚了 —— 因为那时候你已经把"手感差"归因到敌人身上了。

**第二条：没有版本对照的习惯。**
手感调参最大的敌人不是调不出来，是**你忘了昨天那版长什么样**。每天结束做两件事，成本 2 分钟：

```bash
"D:/Git/bin/git.exe" add -A
"D:/Git/bin/git.exe" commit -m "M1: acceleration 45->70，起步手感变硬"
```
外加把一段 10 秒录屏存到 `documents/clips/`。它会在第 5 天救你一次。

**第三条：「看不懂的代码不许进项目」没写进去。**
你是零代码起步，AI 写的代码**能跑，但不一定对**。加一条硬规矩：

> 任何 AI 交付的脚本，AI 必须同时说清三件事：**它放在哪、它依赖什么、参数在哪改。**
> 说不清，就不要。不是因为优雅 —— 是因为两天后你得自己改它。

1. 连续两天你没有主动想打开 Godot → 停
2. 你发现自己真正兴奋的是**设定 / 故事**，而不是"把它做成可玩的东西" → 停，换一个不需要引擎的载体
3. `acceleration` 怎么调都没有"我控制得住身体"的感觉 → 换技术方案，**不是**加时间
